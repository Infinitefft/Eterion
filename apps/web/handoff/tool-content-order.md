# 工具调用与正文的展示顺序

前端已支持按工具开始的位置，将同一条 Assistant 正文拆成多个展示片段。
消息仍只保存一份完整 `content`，工具完成或失败只更新原工具项，不改变插入位置。
Thinking 和 HITL 的展示方式保持不变。

## 后端需要提供的位置

在 `tool.started.payload` 和 Snapshot 中 `kind: "tool"` 的 block 上提供：

```ts
contentOffset?: number;
```

- 表示该工具开始时，其所属 Run 的 Assistant 正文已经输出了多少个 UTF-16 code unit。
- 与 JavaScript 的 `content.length` 和 `content.slice()` 使用相同单位，不是 UTF-8 字节数。`你好🙂` 的长度是 4。
- 在工具开始时确定并持久化；后续完成、失败不能重新计算。相同位置的工具保持原事件顺序。
- 该位置可放进已有 `agent_blocks.data` JSON，不必新增表或数据库列。
- 正文为 `先查资料。资料结论。`、位置为 5 时，展示为 `先查资料。 → 工具 → 资料结论。`。

## 当前前端行为及限制

- 实时事件未提供字段时，Store 用该 Run 当前正文的 UTF-16 长度记录位置。
- 同一页面重新拉取快照时，优先使用后端字段；缺少字段时保留已知工具的本地位置。
- 完全刷新后，如果快照没有该字段，无法从一整段正文和工具结果推断历史插入位置，仍按原方式放在正文前。
- 旧数据没有保存的位置无法准确补算，不能用工具完成时间、正文总长度或 `lastSeqId` 猜测。

本次前端修改没有改动后端；要保证刷新后仍保留交错顺序，需要后端补齐上述字段。
